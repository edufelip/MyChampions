## Notes
- TC-514/TC-518 deterministic native phases isolate contradictory entitlement expectations: AI meal-analysis paywall and success assertions run in separate fresh-Metro invocations selected by an explicit runner scenario, with both access-granting entitlements lapsed or active together; an authenticated direct run with a missing or invalid scenario fails before Detox can report zero coverage as green. Student dashboard and relationship stories launch a fresh app instance with synchronization disabled in `launchArgs` for every case, and Android CI-eligible Detox specs never use `reloadReactNative()` across Detox's idling registry.
- `test:e2e:ios:debug:smoke` builds and runs unauthenticated auth-entry and authenticated role/connection smoke modes separately because the E2E auth-session fixture intentionally bypasses the sign-in screen. The authenticated mode supplies only deterministic invite, QR, and active-nutrition fixtures and never writes to a backend.
- Android Detox debug builds use `devDebug`. The default Android Detox build/test commands and the `*:prod-debug` aliases use secret-free `android.emu.prodDebug`; `*:android:release` explicitly selects strict `android.emu.release` for CI-signed or prebuilt `productionRelease` evidence. The default `Pixel_10` AVD contains Google Play packages but still requires an authenticated licensed tester account and a Play-distributed, correctly signed build before it can provide platform billing evidence.
- Android `productionRelease` is intentionally unavailable without the CI-owned version code and complete private signing inputs. The explicit Detox release build requires `CI_VERSION_CODE` at its shell boundary and forwards it as the Gradle `CI_VERSION_CODE` property. The release workflow is responsible for creating the ignored `android/keystore.properties` and keystore file before requesting the signed AAB.
