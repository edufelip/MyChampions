## Notes
- TC-514/TC-518 deterministic native phases isolate contradictory expectations: AI meal-analysis paywall and success assertions run in separate fresh-Metro invocations selected by an explicit runner scenario, with both access-granting entitlements lapsed or active together. Custom-meal image upload runs its native source-sheet assertion with the synthetic success fixture cleared and its preview assertion in a separate success-fixture invocation. An authenticated direct run with a missing or invalid scenario fails before Detox can report zero coverage as green. Each fresh Metro invocation fully streams its rewritten Expo iOS or Android development bundle before Detox launches. Student dashboard and relationship stories launch a fresh app instance with synchronization disabled in `launchArgs` for every case, and Android CI-eligible Detox specs never use `reloadReactNative()` across Detox's idling registry. The Android job restarts ADB only after its shared-host hook owns the runner, rejects stale device/QEMU/`5554/5555` state, preboots `Pixel_10` on `emulator-5554`, and proves the exact PID/UID/Linux start-time identity, expected AVD/port command, device, AVD, and boot state before Detox reuses it. Android instrumentation synchronously sets `debug_http_host=localhost:8081` before React Native starts and fails if the preference cannot be stored, pairing every debug launch with the configured ADB reverse port instead of the emulator's `10.0.2.2` gateway. Custom-meal quick logging atomically replaces and verifies the grams value, explicitly dismisses Gboard or the iOS accessory keyboard, and submits only through the stable confirm identifier.
- The SC-207 nutrition-builder native flow explicitly submits the focused search editor, waits for two stable actionable searched-food samples before selection, and verifies the selected-food mount before scrolling. After the native deletion alert, short attribute polls first prove the zero-calorie total and then require two consecutive misses for the removed food row, avoiding one long native negative matcher across the alert animation; the displayed calorie total remains the final state assertion.
- The student-home empty-state flow first verifies the visible dashboard and hydration summary, then scrolls the semantic home container to expose the training and nutrition plan CTAs on compact native viewports before asserting them.
- `test:e2e:ios:debug:smoke` builds and runs unauthenticated auth-entry and authenticated role/connection smoke modes separately because the E2E auth-session fixture intentionally bypasses the sign-in screen. The authenticated mode supplies only deterministic invite, QR, and active-nutrition fixtures and never writes to a backend.
- Android Detox debug builds use `devDebug`. The default Android Detox build/test commands and the `*:prod-debug` aliases use secret-free `android.emu.prodDebug`; `*:android:release` explicitly selects strict `android.emu.release` for CI-signed or prebuilt `productionRelease` evidence. The default `Pixel_10` AVD contains Google Play packages but still requires an authenticated licensed tester account and a Play-distributed, correctly signed build before it can provide platform billing evidence.
- Android `productionRelease` is intentionally unavailable without the CI-owned version code and complete private signing inputs. The explicit Detox release build requires `CI_VERSION_CODE` at its shell boundary and forwards it as the Gradle `CI_VERSION_CODE` property. The release workflow is responsible for creating the ignored `android/keystore.properties` and keystore file before requesting the signed AAB.
- TC-519 proves CI trust, isolation, and repository enforcement only. It does not
  authorize provider-console changes, deployment, production credentials, store
  distribution, or provider-live purchase/restore claims.
- The repository variable `MYCHAMPIONS_ENABLE_IOS_TESTS` is default-on: an
  exact value of `false` skips new iOS test-only jobs and the final selective
  gate allows their intentional skip; unset or any other value keeps iOS tests
  enabled. It does not cancel already-running jobs or gate release/distribution
  workflows.
- TC-519's executable contract must cover `SIGINT`/`SIGTERM`, workspace-link and
  runner-temp secret-target removal, interrupted UUID/PID ownership handoff,
  cleanup failure with retained durable records, exact next-run retry,
  malformed/incomplete ledger rejection, bounded `130`/`143` exit,
  outer-supervisor grace through the coordinator's detached invocation/Metro
  process-group `TERM`/`KILL`, supervised-child termination, and
  unrelated-resource preservation. It must also prove that
  `ENV_FILE_CONTENT` is consumed only by the atomic runner-temp writer and unset
  before Yarn, Gradle, `xcrun`, or recovery subprocesses, after which the secret
  bytes live only in the exact mode-`0600` target until cleanup. Native ledger
  fixtures require the runner service's `MYCHAMPIONS_NATIVE_STATE_ROOT` to be an
  absolute canonical, runner-owned, non-symlink, mode-`0700` persistent
  directory outside the workspace and `$RUNNER_TEMP`, accessed only while the
  host lock is held. The Mac value
  `/Users/eduwaldo/.local/state/github-actions/mychampions-native-recovery` was
  configured/read back on 2026-07-29; the intended WSL value
  `/home/eduardo/.local/state/github-actions/mychampions-native-recovery`
  remains pending current endpoint recovery. Even a green local fixture does
  not satisfy the required live mid-build/mid-test cancellation evidence on
  either host.

  bases `main`, `release/**`, and `hotfix/**`; an authorized same-upstream owner

  trigger or branch-sourced definition. Protected-`main` freshness must precede
  the PR preflight, and checked-in merge-group handling remains future-compatible
